## Authentication and Security

### Mobile

- Axios request/response interceptors and a refresh retry path exist in `src/services/api/client.ts`.
- SecureStore is used by the auth service for the demo token; this is preferable to AsyncStorage, but production token/session restoration has not been integration-tested.
- Demo auth persists `MOCK_TOKEN`, which must be impossible in a production build.
- No proof was obtained for protected-action replay safety. Payment, booking confirmation, delete, reward claim and sensitive messaging must be `RECONFIRM` or `NEVER_REPLAY`, not silent auto-replay.
- Search results did not establish full 401/403/429 UI behavior across all domains.

### Web

- The codebase contains user session, cookie, CSRF, refresh, next-path and guard utilities; tests include 12 user-auth security tests and 3 RBAC tests.
- Build and tests are positive evidence, not proof of production cookie/TLS/domain settings.
- Admin pages are correctly treated as separate from public/user coverage.
- Audit `middleware.ts`, BFF allowlists and environment values in deployment review; live authorization remains UNKNOWN.
